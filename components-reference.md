# Leviticus — component reference

Generated by `python -m biblecore build` from the components this book enables in `book.json`. Don't edit. The style reference's section 4 lists the base components and any book-specific notes. Any unit may use any component listed here.


## echo — a verse-level cross-book echo ("cf.")

```html
<p class="v"><span class="n">3</span> …</p>
<aside class="echo" data-anchor="1:3">Deut 11:24 gave the same promise; Josh 1:3 repeats it almost word for word.</aside>
```

- **Following sibling** of the verse, like `.gloss`. Never nested in a gloss, always closed.
- `data-anchor` = the verse it follows (`C:V`); build checks it.
- Site prepends "cf." and folds it into the verse's note toggle: don't write "cf.".
- Verse-level link only. One word's history → that root's `echo` field.
- Harvested into `data/canon.json`: don't repeat in `intertext[]`.

**Verified =** target verse read, and link rests on shared words, a shared phrase or a recognised type-scene, not just a shared theme.


## list — a count or list table (census, roster, allotment)

```html
<section class="block">
  <h2>The first accounting <span class="cap">· 1:20–46</span></h2>
  <table class="list" data-verses="1:20–43">
    <thead><tr><th>Tribe</th><th>Counted</th></tr></thead>
    <tbody><tr><td>Reuven</td><td>46,500</td></tr></tbody>
    <tfoot><tr><td>All Israel</td><td>603,550</td></tr></tfoot>
  </table>
</section>
```

- Inside a `section.block`, in line with the text (not hoisted with the structure blocks). First row = header row of `<th>`; every row has the same number of cells.
- Last column = the number, right-aligned. A total the text gives → `<tfoot>`.
- Cells may carry `data-root` spans, tracked threads too. Inside a `data-verses` table these are summary tags: colour only, no `data-w`; audit counts the declared verses as covered.
- `data-verses` = exactly the verses the table replaces, when it condenses a repeated formula. Say so in the pericope's gloss.

**Verified =** every number and name comes from the verses. Table condenses the text, adds nothing.


## digest — a stretch of verses as one short summary (tiered books)

```html
<section class="block digest" data-verses="24:10–16">
  <h2>The blasphemer <span class="cap">· 24:10–16</span></h2>
  <p>Two or three sentences saying what these verses do, in this study's voice.</p>
</section>
```

- Tiered books only (`book.json` `"tiers": true`). The summary stands in for verses the study doesn't translate here.
- `data-verses` = exactly the verses it replaces; none of them also written out. Tracked spans inside are colour-only (no `data-w`).
- A unit's `digest` (two to four sentences, 80 words at most, in the unit map's Digests section or the meta block's `digest`) is separate: it is the unit's summary on the peaks path, not a block in the fragment.
- Expanding the block on the site shows World English Bible text for its verses, labelled as not this study's translation.

**Verified =** the summary says only what the verses say; the verse range is exact.


## story — an earlier story told beside a verse: a different, earlier event with the same shape, with its background, what's the same, what's different and what it does here

Verse sibling for a *different, earlier* event with the same shape, told with
its background (Herod's feast beside Pharaoh's birthday feast). Same event in
another gospel, or Chronicles beside Kings = `synoptic`, never a story box.
Link one sentence can carry = `aside.echo`.

```html
<aside class="story" data-anchor="14:6" data-kind="type-scene" data-scene="royal-birthday-feast" data-strength="strong">
  <h4><span class="par-title">Pharaoh's birthday feast</span> <span class="par-ref">Gen 40:20–22</span></h4>
  <p class="par-story">Two to four plain sentences telling the earlier story.</p>
  <ul class="par-match"><li>what's the same</li><li>…</li></ul>
  <p class="par-diff">What's different.</p>
  <p class="par-does">What it does here: irony, reversal, identification, fulfilment, warning.</p>
  <p class="par-later">Later reuse, only if there is one.</p>
</aside>
```

- Follows the verse it bears on, or the last verse of the scene it covers;
  `data-anchor` = that verse. `data-span="14:3–12"` optional.
- `data-kind`: `type-scene`, `story`, `allusion`, `character` or `reuse`. A
  `type-scene` box also names it: `data-scene="<id>"`. Check the canon's
  type-scene list first; a new id is the book owner's call.
- `data-strength`: `strong` or `possible`. Ship a `possible` link when it's
  worth Lane's eye, worded as tentative. A weak link never ships as a story
  box: notes or a footnote.
- Required: `<h4>` with `par-title` and `par-ref`, then `par-story`,
  `par-diff`, `par-does`. **No box ships without a stated difference.**
  `par-ref` must include verses (`Exod 24:15–18`); a bare chapter list
  (`Exod 24; 34`) fails at build. `par-match`, `par-later` optional.
- Site supplies the labels (Same, Different, What it does, Later): don't
  write them. Each box hides behind its own ◈ chip ("Type scene" or "Earlier
  story").
- Transliteration only. No `data-root`, `class="r"` or `class="rl"` inside
  (the occurrence scanner counts every `data-root`). Box rests on shared
  words → put them in the box as evidence; no `aside.echo` for the same
  link. Argument about the link → footnote.
- Harvested into `data/canon.json` (an intertext row per reference, a
  type-scene row for `data-scene`): don't repeat in `intertext[]` or
  `typescenes[]`.


## mirror — a passage of the mirrored book beside a verse: the twin text, the words the two share, and what the mirror shows here

For a book with `mirrors` in `book.json`: verse sibling setting the unit's
passage beside its twin in the other book (Numbers 11 beside Exodus 18), with
the words the two share. The pairing is a scholar's reading, never a fact; say
"one reading" if the box needs qualifying. Link one sentence can carry =
`aside.echo`; same event told twice in one book family = `synoptic`;
unrelated earlier story = `story`.

```html
<aside class="mirror" data-anchor="11:14" data-pair="H" data-span="11:10–17">
  <h4><span class="par-title">The burden: too heavy … alone</span>
      <span class="par-ref">Exod 18:13–18</span>
      <span class="strength"></span></h4>
  <div class="row"><span class="src">Exod 18:18</span><span class="txt">… <span class="sh" data-ids="3515">heavy</span> … <span class="sh" data-ids="905">alone</span></span></div>
  <p class="take">What the mirror shows here.</p>
</aside>
```

- Follows the verse it bears on; `data-anchor` = that verse, inside the pair's
  side of this book. `data-span` optional.
- `data-pair` names a pair in the mirror data file (status `seed` or `kept`).
  **Boxes make no claim the data file doesn't hold:** `par-ref` lies inside
  the pair's twin passage, and every `span.sh` carries `data-ids` (Strong's,
  comma-separated) the pair lists under `shared`. Word the pair doesn't list
  → not highlighted.
- Leave `span.strength` empty: build writes the dots (and `data-n`) from the
  data file. Echo-tier pair has no strength span.
- One box per beat. A wide pair (several beats, several units) gets a box in
  each unit it touches: same `data-pair`, own `par-ref` inside the twin
  passage.
- Translate the twin in the unit's own voice: the unit pack's mirror section
  has the Hebrew word order, transliteration and Strong's numbers, with a
  gloss only where the book already has one. **Never raise a strength above
  what the shared words support.** Link the data file doesn't hold → no box;
  propose it in the meta block's `mirror[]`.
- Poetry twin (`poetry` in the pair) → header only: `par-title`, `par-ref`,
  `take`, no rows.
- `take` required: one or two sentences on what the mirror shows here.
- Transliteration only. No `data-root`, `class="r"` or `class="rl"` inside.
- Harvested into `data/canon.json` (an intertext row of kind `mirror` per
  reference in `par-ref`): don't repeat in `intertext[]`.


## ritual — a rite as an ordered strip of steps, each tied to a zone of the tabernacle map (also turns the map on)

A strip of steps in the order the verses give, each placed on the tabernacle
map. Enabling `ritual` also gives the unit a map thumbnail in its header (tap:
the full sheet) and an inset beside each strip; tapping a step lights its zone.

```html
<section class="block ritual" data-verses="1:3–9">
  <h2>The going up offering <span class="cap">· 1:3–9</span></h2>
  <ol class="steps">
    <li data-who="offerer" data-at="entrance">Brings a male without blemish. <sup>1:3</sup></li>
    <li data-who="priest" data-at="altar">Dashes the blood around the altar. <sup>1:5</sup></li>
  </ol>
</section>
<div class="tabmap" data-layer="camp"></div>
```

- `data-who`: `offerer`, `priest`, `high-priest`, `people`. `data-at`: a zone id,
  `outside-camp camp entrance court altar basin holy-place veil most-holy`
  (`veil` is drawn and labelled "curtain"; `most-holy` is the holy of holies).
- Every step carries a `<sup>` verse, and the order is the verses' order.
  Where the text leaves the place or the doer unsaid, pick the zone it
  implies and say so in the unit's notes.
- `data-verses` (on the section) only when the strip replaces those verses.
- `div.tabmap` (empty) puts the map in a unit with no strip: `data-layer`
  `holy` | `enter` | `camp`, `data-at` to light a zone.
- Labels follow `translation-choices.md`; the map's are already set.


## lawparallel — a law restated elsewhere in the Torah: the other passages beside this one, with the stated differences and the text's own reasons

For a law the Torah states in more than one place (`biblecore/laws.json`).
Verse sibling: the other passages of that law, their stated differences and
the text's own reasons. Never a dating or source argument (those live in the
file's `footnote`). A wording link only = `aside.echo`.

```html
<aside class="lawparallel" data-anchor="15:12" data-law="release-of-slaves" data-at="Deut 15:12–18">
  <h4><span class="par-title">Release of a bound Hebrew</span></h4>
  <div class="row"><span class="src">Exod 21:2–6</span><span class="txt">Six years he serves; in the seventh he goes free.</span>
    <span class="diff">(copied from the file)</span><span class="why">(optional, copied)</span></div>
  <p class="take">What the parallel shows here.</p>
</aside>
```

- `data-law` = a law id in the file; `data-at` = this book's passage of it,
  exactly as listed; `data-anchor` = a verse inside it and inside the unit.
- One `div.row` per other passage, `span.src` exactly as the file lists it.
  `span.diff` is **copied verbatim** from that passage's `differences`;
  `span.why`, if used, from its `reasons`. `span.txt` is the unit's own
  rendering. A difference or reason the file lacks → no box; propose it.
- `take` required: one or two sentences. Transliteration only; no
  `data-root`, `class="r"` or `class="rl"` inside.
- Harvested into `data/canon.json` (intertext kind `law`, one row per `span.src`).
- **Briefs** (so a narrative book's echo can open this law): meta-block
  `lawbriefs[]`, each `{law, ref, brief}`. `ref` is a full reference inside
  one of the law's passages (`"Deut 15:1–11"`); `brief` at most two
  sentences. Merged at port into `data/canon.json`, read by the hub; adding
  one needs no re-vendor.
